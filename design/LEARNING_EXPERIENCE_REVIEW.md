# 학습 경험 검토와 개선 · 2026-10-27

## 검토 목적과 범위

처음 배우는 사람이 ‘이 개념이 무엇이며 왜 필요한지’를 이해하고, 작은 예를 설명할 수 있도록 수업의 순서와 활동을 정리했다. 18개 분야, 130개 주제의 공통 구조를 검토하고 520개 단계 본문을 재생성했다. 기존 ui-taste 디자인의 색·타이포그래피·리더 틀을 유지했다.

이번 검토는 소스·운영 화면 관찰, 콘텐츠 일관성 검사, 대표 수업의 브라우저 조작으로 진행했다. 실제 중고등학생이나 비전공자 대상의 학습 효과 실험은 진행하지 않았다. 모든 주제의 전문 지식을 독립적으로 감수했다는 의미는 아니다.

## 발견한 문제와 수정

| 문제 | 학습에 주는 영향 | 수정 |
|---|---|---|
| ‘그림 수업 / 원리 실험 / 문제 탐정’처럼 표현 방식으로 단계 이름을 정함 | 무엇을 배우는 단계인지 예측하기 어려움 | ‘개념 이해 / 작동 원리 / 문제 해결 / 실무 선택’으로 통일 |
| 뜻·용어를 배우기 전에 그림 조작이나 분류를 요구함 | 모르는 상태에서 추측해야 함 | 한 문장 정의 → 필요한 이유 → 용어 → 작은 예 → 비유와 한계 → 관찰 안내 → 활동 → 자기 설명 순서 |
| 핵심 용어를 하나씩 눌러야 읽을 수 있음 | 정의를 비교하려면 계속 앞뒤로 이동해야 함 | 모든 핵심 용어를 정의 목록으로 함께 표시 |
| 50개 입문 길잡이의 예시가 수업 생성 과정에서 빠짐 | 비유와 실제 개념 사이의 연결이 약함 | 기존 예시 50개 복원, AI·데이터·프로젝트 등 확장 분야에 주제별 예시 80개 작성 |
| 원리 설명의 기술 자료를 기본적으로 접어 둠 | 세 문장의 개요가 설명의 전부처럼 보임 | 원리·코드·상세 사례를 처음부터 펼치고 필요할 때 접도록 변경 |
| 57개 주제의 ‘모션’이 시간에 따라 문장과 점 위치만 변경함 | 동작 모형처럼 보이나 인과 관계를 새로 보여 주지 않음 | 세 단계를 함께 읽는 순서 목록으로 변경. 실제 입력·결과가 변하는 실험은 유지 |
| 일부 공통 문제 해결 카드가 요약문을 이어 붙인 형태 | 증상과 증거가 다른 사건을 설명함 | 근거 없는 자동 카드 합성을 제거. 확장 분야의 명시적 사례와 수동 교정 사례만 카드로 표시 |
| 프로세스 주제의 도입은 주방, 설명은 사무실 비유 | 같은 개념을 다시 해석해야 함 | 사무실 비유로 통일하고 사진 편집기의 실제 예로 연결 |
| 프로세스/스레드 비교표의 ‘장애 위험’이 스레드의 ‘얻는 점’으로 추출됨 | 장점과 위험이 뒤바뀜 | 데이터 공유의 이득과 동기화·장애 전파의 부담을 직접 작성 |
| VM/컨테이너의 메모리 부족 증상에 파일 유실 단서가 섞임 | 서로 다른 문제의 원인이 연결됨 | 메모리 사용량·컨테이너 한도·부하 재검증으로 일관된 사례 구성 |
| AI 분류 활동이 포함 관계를 충분히 보여 주지 않음 | 머신러닝과 딥러닝을 같은 범주로 오해할 수 있음 | AI ⊃ 머신러닝 ⊃ 딥러닝 포함 그림, 같은 스팸 메일 문제에서 규칙/학습 비교 |
| 인출 활동이 ‘생각했어요’ 버튼만 제공 | 스스로 설명했는지 확인하기 어려움 | 선택 입력란과 예시 답안 비교. 메모는 채점·저장하지 않는다고 안내 |
| 논리 게이트 상태 문장이 ‘둘 다 1일 때만 결과는 0’처럼 읽힘 | 규칙과 현재 출력이 충돌 | 게이트 규칙을 먼저 설명하고 현재 A/B 값과 결과를 별도로 표시 |
| 영어 용어를 함수 이름 안에서도 치환함 (`pthread_join`의 `thread`) | 코드 이름이 쪼개져 읽힘 | 영어 별칭에는 식별자 경계를 적용. 한국어 조사 연결은 지원 |
| 전역 용어 풀이가 가상 메모리를 디스크 확장으로만 설명함 | 본문의 주소 변환 설명과 충돌 | 주소 대응과 접근 권한 중심으로 교정. 인덱스·캐시·핸드셰이크·지연 시간 등의 과도한 일반화도 교정 |

## 새 수업의 기준

1. 첫 문장으로 개념의 뜻을 알 수 있어야 한다.
2. 활동 전에 용어와 같은 주제의 구체적인 작은 예를 제시한다.
3. 그림을 넣으면 무엇을 조작하고 어떤 차이를 볼지 안내한다.
4. 비유가 실제 원리와 달라지는 지점을 밝힌다.
5. 문제 사례의 증상·증거·원인 후보·수정·재검증이 같은 사건을 설명해야 한다.
6. 초심자는 먼저 ‘개념 이해’에서 자기 말로 설명한다. 다음 단계에서 기술적 깊이를 넓힌다.
7. 예시 답안을 맞는 문장으로 외우게 하지 않고 자신의 설명에서 빠진 개념을 비교하도록 안내한다.

## 변경 데이터와 배포 방법

- `worked-examples.json`: 새로 작성한 80개 구체 예시.
- `teaching-overrides.json`: 프로세스/스레드, VM/컨테이너, AI 포함 관계, 논리 게이트의 개별 교정.
- `build-classroom.ts`: 원본 길잡이·확장 자료·개별 교정으로 130개 수업과 본문 생성.
- 기존 L2~4 기술 자료 390개를 보존한다. 퀴즈·채점·사용자 기록과 아티클 공개 상태는 수정하지 않는다.
- 운영 아티클 수정 전 130개 본문의 해시를 `revision-baseline-20261027.json`에 기록했다. 수정 전 본문은 Git `624cdace5f362e327a83fb378ad05de947ef88c5`의 `content/readable-library.json`으로 복원할 수 있다.
- SQL은 18개 분야별로 행을 잠그고 현재 본문이 수정 전/후 해시와 일치할 때만 네 본문 필드를 갱신한다. 누락이나 동시 수정은 해당 분야 전체를 중단하며 반복 실행은 추가 갱신하지 않는다.

## 검증 결과

- ESLint, TypeScript, Next.js 프로덕션 빌드 통과.
- `content:verify-classroom`: 130개 아티클 / 520개 단계 / 732개 학습 블록 SSR 검증. 설명·예시가 활동 앞에 있는지, 관찰 안내가 있는지, 390개 기술 자료와 128개 퀴즈 세트가 보존되는지 확인.
- 14개 학습 형식과 진리표·부호 비트·대기열·분류 임계값·평균/중앙값·유사도·기울기·Attention 행 합·일정 계산 검사 통과.
- `content:verify`: 라이브러리 128개 아티클 / 512개 단계 / 512개 퀴즈 검사. Python 92개, JS/TS 2개, SQL 4개 예제 실행. 별도 기초 샘플을 포함한 DB 시드 결과는 130개 아티클 / 528개 퀴즈, 미포함 주제 0개.
- `verify-classroom-revisions`: 130개 수정의 해시 일치, 동시 수정 거부, 분야 단위 원자성, 반복 실행 시 추가 갱신 없음 확인.
- 브라우저: 390×844와 320×740에서 단계 이름·기본 본문·자기 설명/예시 답안·AI 포함 그림·분류 피드백·원리 자료 기본 펼침·스레드 장단점·논리 게이트 입력/출력을 확인. 문서 가로 넘침과 학습 영역 가로 넘침 없음.
- 영어 함수 이름의 일부가 용어 버튼으로 변하지 않는 회귀 검사와 실제 `pthread_join` 본문 확인. 로컬 콘솔 오류·경고 없음.

## 다음 품질 판단 기준

실제 입문자에게 5~10분 동안 대표 수업을 사용하게 하고, 도움 없이 ‘개념 한 문장 설명 → 새 사례 판단 → 이유 말하기’를 할 수 있는지 관찰해야 한다. 이 결과로 비유와 용어 수, 예제의 크기를 조정한다. 현재 수정은 이해를 방해하던 구조와 불일치를 줄인 결과이며 학습 성과가 측정된 결과는 아니다.

용어 교정에 참고한 1차 자료: [Linux Page Tables](https://cdn.kernel.org/doc/html/latest/mm/page_tables.html), [PostgreSQL Index Types](https://www.postgresql.org/docs/current/indexes-types.html). 각 주제의 기존 기술 자료와 출처는 유지했다.
