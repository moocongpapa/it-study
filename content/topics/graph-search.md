# DFS와 BFS — 연결된 곳을 방문하는 두 순서

> **한 문장으로:** 한 길을 깊게 따라가거나 가까운 곳부터 넓게 살피는 방식으로 연결 관계를 탐색합니다.

## 왜 필요한가요?

친구 관계, 지하철 역, 웹 링크는 한 줄로만 연결되지 않습니다. 이런 연결에서 갈 수 있는 곳과 경로를 찾아야 합니다.

## 일상에서 떠올려 보기

미로에서 한 갈림길을 끝까지 가 본 뒤 돌아오는 방법이 DFS에 가깝습니다. 출발점에서 한 칸 거리인 곳을 모두 보고, 다음에는 두 칸 거리인 곳을 보는 방법이 BFS에 가깝습니다. 이미 간 곳에는 표시를 남깁니다.

## 순서대로 따라가기

1. 출발 지점을 정하고 방문했다고 표시합니다.
2. DFS는 한 방향을 깊게 따라가고, BFS는 먼저 발견한 가까운 지점을 먼저 처리합니다.
3. 새 이웃을 발견하면 기록하고 계속 진행합니다. 방문 표시로 반복 연결을 무한히 돌지 않게 합니다.

```mermaid
flowchart LR
 A["출발"] --> B["이웃 B"]
 A --> C["이웃 C"]
 B --> D["더 먼 이웃 D"]
 C --> D
```

## 작은 예로 확인하기

A에서 B와 C로 한 번에 갈 수 있고 B에서 D로 한 번에 갈 수 있습니다. BFS는 B와 C를 먼저 살핀 뒤 D를 살핍니다. 모든 이동의 비용이 같다면 처음 찾은 최소 이동 횟수의 경로를 사용할 수 있습니다. 길마다 시간이 다르면 최소 시간 문제는 별도로 풀어야 합니다.

## 처음 만나는 용어

| 용어 | 쉬운 뜻 |
|---|---|
| 그래프 | 지점과 지점 사이의 연결을 나타내는 구조입니다. |
| 정점·간선 | 지점과 그 지점을 연결하는 관계입니다. |
| DFS | 한 연결 방향을 깊게 따라가며 탐색하는 방법입니다. |
| BFS | 출발점에서 가까운 단계부터 넓게 탐색하는 방법입니다. |

**비유의 한계:** BFS의 최소 이동 횟수가 항상 최소 시간이나 최소 요금을 뜻하지는 않습니다. 연결마다 비용이 다른 문제에서는 그 비용을 고려하는 다른 방법이 필요합니다.

## 스스로 확인

모든 길의 이동 비용이 같을 때 최소 간선 수 경로를 찾는 데 어느 방법이 알맞을까요?

**답과 이유:** BFS입니다. 가까운 단계부터 처리하므로 처음 발견한 도착 경로의 이동 횟수가 최소가 됩니다.

# 큐, 방문 시점, 경로 복원

<!-- beginner-guide:start -->
## 읽기 전 길잡이

아래 코드에서 대기 목록과 방문 기록을 구분해 보세요. 발견할 때 표시하는 이유와, 어느 지점에서 왔는지 기록해 경로를 복원하는 부분을 차례로 읽습니다.

## 이 단계에서 만날 말

| 용어 | 쉬운 뜻 |
|---|---|
| 큐 | 먼저 넣은 항목을 먼저 꺼내는 대기 목록입니다. |
| 스택 | 마지막에 넣은 항목을 먼저 꺼내는 목록입니다. |
| 인접 리스트 | 각 지점에 연결된 이웃 목록입니다. |
| 방문 집합 | 이미 발견한 지점을 기록한 자료입니다. |
| 가중치 | 이동 시간이나 비용처럼 연결에 붙인 값입니다. |
| 경로 복원 | 도착점까지 어느 지점을 거쳤는지 다시 찾는 것입니다. |

<!-- beginner-guide:end -->

인접 리스트는 각 정점의 이웃을 저장한다. V개 정점 E개 간선의 BFS/DFS는 일반적인 인접 리스트 구현에서 O(V+E) 탐색 비용을 갖는다. BFS는 발견해 큐에 넣는 시점에 방문을 표시해야 같은 정점이 과도하게 중복 삽입되는 것을 막는다.

Python 3 예제는 BFS로 가중치 없는 최단 경로를 복원한다.

```python
from collections import deque
graph = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}
parent, queue = {"A": None}, deque(["A"])
while queue:
    node = queue.popleft()
    for neighbor in graph[node]:
        if neighbor not in parent:
            parent[neighbor] = node
            queue.append(neighbor)
path, current = [], "D"
while current is not None:
    path.append(current); current = parent[current]
print(path[::-1])  # A, B, D (이웃 순서에 따른 한 경로)
```

같은 길이 경로가 여러 개면 이웃 순서에 따라 반환 경로가 달라질 수 있다. DFS의 재귀 스택도 메모리를 쓴다. 매우 깊은 그래프에서는 명시적 스택을 검토한다. 방향 그래프의 순환 탐지는 단순 visited만이 아니라 현재 탐색 경로 상태 등을 구분해야 한다.

# 가상 장애 — 추천 관계 탐색이 폭발한다

<!-- beginner-guide:start -->
## 읽기 전 길잡이

같은 지점이 대기 목록에 반복해서 들어가면 작업량이 크게 늘 수 있습니다. 방문 표시를 언제 하는지와 서로 연결된 순환 경로를 먼저 확인하세요.

<!-- beginner-guide:end -->

가상 추천 그래프에서 방문 처리를 dequeue 시점에만 해 다수 이웃이 같은 노드를 큐에 반복 넣는다. 큐 길이가 커지고 메모리를 소모한다. 노드·간선 수, 실제 enqueue 수, 중복률을 비교한다.

**수정:** 발견 시점에 방문을 기록하고 탐색 깊이·전체 방문 수·시간 예산을 둔다. 깊이 제한을 두면 완전한 최단 경로/도달성 보장이 제한될 수 있음을 API에 명시한다. DB에서 이웃을 매 노드마다 조회하면 N+1 I/O가 비용을 지배할 수 있어 묶음 조회나 그래프 저장 모델을 검토한다.

**재검증:** 자기 루프·순환·다중 경로·고립 정점·허브 노드·끊긴 목적지를 포함한다. 결과 정확성과 큐 최대 크기, 조회 횟수, 제한 초과 응답을 확인한다.

# 그래프 목적과 자원 제한

<!-- beginner-guide:start -->
## 읽기 전 길잡이

메모리 한도와 필요한 결과를 먼저 정합니다. 모든 도달 지점이 필요한지, 한 경로가 필요한지, 이동 비용을 고려해야 하는지에 따라 탐색 방법을 비교하세요.

<!-- beginner-guide:end -->

| 목적 | 알고리즘 출발점 | 전제 |
|---|---|---|
| 가중치 없는 최단 경로 | BFS | 간선 비용이 동일 |
| 깊은 구조·도달성 탐색 | DFS | 방문·스택 관리 |
| 비음수 가중 최단 경로 | Dijkstra | 우선순위 큐·가중 조건 |
| 선수 지식 순서 | 위상 정렬 | 방향 비순환 그래프 |

이 앱의 선수 관계는 DAG여야 하므로 새 간선이 순환을 만드는지 검증한다. UI 배치가 예쁘다고 그래프 무결성이 보장되는 것은 아니다. 대형 그래프는 전체를 클라이언트로 전송하기보다 부분 그래프·캐시·서버 탐색과 권한을 설계한다.

**판단 연습:** “이 토픽의 모든 선수”와 “친구 사이 최단 연결”은 같은 질의인가? 결과 크기·권한·탐색 깊이·정확성 계약을 정하고 알고리즘을 선택하자.

참고: [Princeton Undirected Graphs](https://algs4.cs.princeton.edu/41graph/), [Princeton Directed Graphs](https://algs4.cs.princeton.edu/42digraph/).
