# 동기화와 데드락 — 함께 일할 때 지켜야 할 순서

> **한 문장으로:** 공유하는 데이터를 안전하게 바꾸려면 작업 순서를 조정하고, 서로 영원히 기다리는 상황을 막아야 합니다.

## 왜 필요한가요?

두 요청이 마지막 상품 한 개를 동시에 주문하면 둘 다 재고가 있다고 판단할 수 있습니다. 여러 작업이 같은 데이터를 확인하고 바꿀 때 결과를 지키는 규칙이 필요합니다.

## 일상에서 떠올려 보기

한 장뿐인 공용 예약표를 고칠 때는 한 사람이 끝낸 다음 다른 사람이 확인하도록 합니다. 그런데 A는 열쇠를 갖고 도장을 기다리고, B는 도장을 갖고 열쇠를 기다리면 둘 다 진행하지 못합니다. 이런 서로 기다림이 데드락의 비유입니다.

## 순서대로 따라가기

1. 함께 바꾸는 데이터와 반드시 지켜야 할 규칙을 찾습니다.
2. 확인과 변경을 한 묶음으로 보호해 다른 작업이 중간에 끼어들지 않게 합니다.
3. 여러 잠금을 쓴다면 모두 같은 순서로 얻는 등 서로 기다림을 막는 규칙을 정합니다.

```mermaid
flowchart LR
 A["재고 확인과 차감"] --> B["한 작업씩 보호"] --> C["재고 규칙 유지"]
 D["A는 열쇠 보유"] --> E["B의 도장 대기"]
 F["B는 도장 보유"] --> G["A의 열쇠 대기"]
```

## 작은 예로 확인하기

재고가 1개일 때 ‘재고 확인’과 ‘재고 차감’을 따로 하면 두 작업이 모두 확인을 통과할 수 있습니다. 두 행동 전체를 같은 보호 범위에 넣어야 합니다. 숫자 하나를 안전하게 증가시키는 원자 연산만으로 재고와 주문 내역의 모든 관계가 보호되지는 않습니다.

## 처음 만나는 용어

| 용어 | 쉬운 뜻 |
|---|---|
| 동기화 | 여러 작업의 접근과 순서를 맞추는 것입니다. |
| 잠금(lock) | 다른 작업이 기다리도록 공유 자원 사용을 조정하는 도구입니다. |
| 임계 구역 | 함께 사용하는 데이터를 안전하게 다루기 위해 보호하는 코드 범위입니다. |
| 데드락 | 작업들이 서로 가진 자원을 기다려 더 이상 진행하지 못하는 상태입니다. |

**비유의 한계:** 잠금을 많이 걸면 항상 안전하고 빠른 것은 아닙니다. 잠금 순서가 꼬이면 데드락이 생기고, 기다림이 길면 속도가 떨어집니다. 무엇을 얼마나 오래 보호할지 정해야 합니다.

## 스스로 확인

A는 열쇠를 기다리고 B는 도장을 기다리는데, 서로 필요한 물건을 상대가 쥐고 있습니다. 무엇을 바꾸면 도움이 될까요?

**답과 이유:** 모든 작업이 열쇠를 먼저 얻고 도장을 나중에 얻도록 순서를 통일하는 방법이 있습니다. 서로 다른 순서로 잡는 순환 기다림을 줄일 수 있습니다.
<!-- level:2 -->
# 임계 구역의 기준은 데이터의 불변식

<!-- beginner-guide:start -->
## 읽기 전 길잡이

예제에서 확인과 변경이 같은 보호 범위에 들어 있는지 보세요. 깨어났다는 사실만으로 원하는 상태가 됐다고 가정하지 않고 조건을 다시 확인하는 이유도 함께 읽으세요.

## 이 단계에서 만날 말

| 용어 | 쉬운 뜻 |
|---|---|
| 불변식 | 작업 전후에 반드시 지켜야 하는 업무 규칙입니다. |
| 뮤텍스 | 한 작업자만 보호 구역에 들어오게 하는 잠금입니다. |
| 조건 변수 | 특정 상태가 될 때까지 기다렸다가 다시 확인하게 하는 도구입니다. |
| 원자 연산 | 중간에 다른 작업이 끼어들지 않도록 보장된 단일 연산입니다. |
| 경합 | 여러 작업이 같은 자원을 쓰려고 경쟁하는 것입니다. |
| 기아 | 다른 작업에 계속 밀려 특정 작업이 오래 진행하지 못하는 현상입니다. |

<!-- beginner-guide:end -->

“재고가 0 아래로 내려가지 않는다”라는 규칙을 지키려면 확인과 차감이 같은 임계 구역 안에 있어야 한다. 가시성과 메모리 순서도 동기화 계약의 일부다. 조건 변수는 상태가 원하는 조건이 될 때까지 기다리는 도구이며 깨어났다는 이유만으로 조건이 참이라고 가정하지 않는다. predicate를 반복 확인한다.

Python 3의 단일 프로세스 스레드 예제다. GIL을 업무 불변식의 잠금으로 대신하지 않는다.

```python
from threading import Lock, Thread
stock, sold = 1, 0
lock = Lock()
def buy():
    global stock, sold
    with lock:
        if stock > 0:
            stock -= 1
            sold += 1
workers = [Thread(target=buy) for _ in range(20)]
for worker in workers: worker.start()
for worker in workers: worker.join()
assert stock == 0 and sold == 1
```

컨텍스트 매니저는 예외가 나도 잠금을 해제하도록 돕는다. 여러 락이 필요하다면 모든 경로에서 동일한 순서로 획득한다. 락을 가진 채 외부 네트워크 호출을 수행하면 대기 시간이 길어지며 순환 의존성도 생길 수 있다. 서로 다른 프로세스나 DB 트랜잭션에는 다른 잠금 경계가 필요하다.

# 재현 사례 — 두 계좌를 반대 순서로 잠근다

<!-- beginner-guide:start -->
## 읽기 전 길잡이

프로그램이 멈춘 듯 보이면 각 작업자가 무엇을 가진 채 무엇을 기다리는지 목록으로 적어 봅니다. 단순히 느린 작업과 서로 진행할 수 없는 작업을 구분하는 것이 조사 출발점입니다.

<!-- beginner-guide:end -->

가상 송금 코드가 A→B에서는 A 락 뒤 B 락, B→A에서는 B 락 뒤 A 락을 잡는다. 두 요청이 동시에 실행하면 서로를 기다릴 수 있다.

```text
thread-1 holds account-A; waits account-B
thread-2 holds account-B; waits account-A
```

모든 스레드의 스택을 같은 시점에 수집하고 보유·대기 락을 그래프로 그린다. “CPU가 낮다”만으로 데드락이라고 단정하지 말고 I/O 대기와 조건 변수 대기도 확인한다. 재현에는 barrier를 써 획득 순서를 맞출 수 있지만 실제 운영에서 강제 무한 대기를 만들지 않는다.

**수정:** 계좌 ID 등 안정된 키 순서로 락을 획득하고 역순으로 해제한다. 임계 구역을 작게 하며 타임아웃·취소·재시도에는 자원 정리를 포함한다. 타임아웃만 추가해도 중간 변경의 무결성은 자동 복구되지 않는다.

**재검증:** 반대 방향 요청, 예외, 취소, 중복 요청을 함께 실행한다. 계좌 총합 같은 불변식과 락 대기 시간, 처리량을 확인한다. C/C++의 데이터 레이스에는 ThreadSanitizer가 보조 수단이다.

# 동기화 전략을 고르는 기준

<!-- beginner-guide:start -->
## 읽기 전 길잡이

공유를 줄이거나 한 작업자에게 소유권을 주면 잠금 자체를 줄일 수 있습니다. 처리 속도, 데이터 전달 비용, 코드의 이해 가능성을 함께 비교하세요.

<!-- beginner-guide:end -->

| 전략 | 유리한 작업 | 부담 |
|---|---|---|
| 단일 뮤텍스 | 단순한 복합 불변식 | 병목·긴 임계 구역 |
| 세분화 락 | 독립 키의 병렬 변경 | 잠금 순서·관리 복잡성 |
| atomic/CAS | 작은 상태의 경쟁 갱신 | 메모리 순서·ABA·재시도 비용 |
| 소유권과 메시지 전달 | 공유 가변 상태 최소화 | 큐·지연·분할 설계 |

lock-free는 각 스레드가 반드시 기다리지 않는다는 뜻이 아니며 wait-free와 다르다. 읽기 쓰기 락도 읽기 비율이 높다는 이유만으로 항상 빠르지 않다. 업무 불변식부터 정하고 도구의 보장 범위를 확인한다.

대규모 서비스에서는 전역 락을 분산 락으로 바꾸기 전에 상태를 키별로 분할하거나 DB 원자 갱신으로 표현할 수 있는지 본다. 분산 락은 lease 만료·네트워크 분할·오래된 소유자의 쓰기 문제까지 고려해야 한다. 락 대기 시간, 충돌률, 취소와 복구를 SLO와 연결한다.

**판단 연습:** 인기 상품 한 개와 수만 개의 독립 상품 재고를 같은 잠금 방식으로 처리해야 할까? 정확성과 핫키 부하를 기준으로 선택하자.

참고: [Python threading](https://docs.python.org/3/library/threading.html), [Clang ThreadSanitizer](https://clang.llvm.org/docs/ThreadSanitizer.html).
