# 토큰·문맥 창·잘림과 생성 길이

> **먼저 한 문장:** 모델은 글자 수가 아닌 토큰으로 입력과 출력을 다루며 문맥 예산을 넘으면 필요한 정보가 누락되거나 요청이 실패할 수 있습니다.

문서를 길게 넣었는데 앞부분을 놓치거나 답이 잘리는 일이 있습니다. 모델이 읽고 쓸 수 있는 양의 제한을 알면 중요한 정보를 배치하고 비용과 실패를 줄일 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"tokens-context-windows","view":"words"}
```

## 작은 예로 이해하기

모델이 한 번에 다룰 수 있는 입력과 출력의 공간을 책상이라고 생각해 보세요. 문서, 대화 기록, 지시가 공간을 차지하고 답을 쓸 자리도 필요합니다. 토큰은 글을 처리하는 작은 조각이며 한 글자와 항상 같지는 않습니다. 긴 문서를 무조건 붙이면 뒤의 내용이 빠지거나 요청 자체가 거절될 수 있습니다.

## 익숙한 장면과 연결하기

가방에 자료를 넣을 때 종이 장수만 볼 것이 아니라 실제 부피와 돌아올 때 넣을 물건의 공간도 남겨야 하는 것과 비슷합니다.

**비유의 한계 — 이 점은 달라요:** 글자·단어와 토큰은 일대일 관계가 아닙니다. 문맥 한도가 크다고 모든 위치의 정보를 항상 정확히 활용하는 것도 아닙니다.

## 직접 확인하기

입력의 자리과 생성할 답을 번갈아 선택하세요. 바로 아래 설명에서 무엇을 공유하고 무엇이 달라지는지 비교합니다. 버튼을 누르는 것보다 차이를 한 가지 말해 보는 것이 목표예요.

```learning
{"slug":"tokens-context-windows","view":"explore"}
```

```learning

```
