# ETL·ELT와 데이터 파이프라인

> **먼저 한 문장:** 데이터를 옮기는 작업은 한 번의 복사보다 재실행·검증·실패 복구를 포함한 흐름으로 설계합니다.

매번 파일을 내려받고 손으로 붙여 넣으면 누락과 실수가 생깁니다. 자료를 가져와 정리하고 저장하는 흐름을 만들면 반복 업무를 줄이고 실패한 지점도 찾기 쉬워집니다.

## 먼저 알아둘 말

```learning
{"slug":"etl-data-pipelines","view":"words"}
```

## 작은 예로 이해하기

여러 매장의 판매 자료를 매일 모은다고 합시다. 날짜 형식을 맞춘 뒤 저장하면 ETL의 흐름이고, 먼저 모아 저장한 다음 필요에 맞게 바꾸면 ELT의 흐름입니다. 어제 작업을 다시 실행해도 같은 판매가 두 번 더해지지 않도록 원본 식별자와 처리 기록을 관리해야 합니다.

## 익숙한 장면과 연결하기

매장 영수증을 본사 장부로 옮기는 과정과 같습니다. 같은 봉투를 두 번 받거나 늦게 도착해도 총액이 중복되지 않도록 접수 번호와 처리 기록이 필요합니다.

**비유의 한계 — 이 점은 달라요:** 작은 배치 예제로 분산 환경의 정확히 한 번 처리를 보장할 수는 없습니다. 저장 경계와 이벤트의 중복·지연·순서 변경을 별도로 설계해야 합니다.

## 직접 확인하기

가져오기 → 정리하기 → 저장·재시도 순서로 읽어 보세요. 뒤의 과정에서 필요한 것이 앞에서 어떻게 준비되는지 찾습니다. 숫자는 읽는 순서이며 모든 상황이 정확히 세 단계라는 뜻은 아닙니다.

## 읽기 전 길잡이

2. 변환·검증 후 대상에 멱등하게 반영합니다.
3. 진행 위치를 기록하고 실패 구간을 재처리합니다.

## 예제로 확인하기

```python
events=[{"id":"e1","amount":10},{"id":"e2","amount":20}]
store={}
for batch in [events,events]:
    for e in batch: store[e["id"]]=e["amount"]
assert sum(store.values())==30
print(sum(store.values()))
```
