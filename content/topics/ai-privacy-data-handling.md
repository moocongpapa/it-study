## 읽기 전 길잡이

AI에 전달하고 기록하는 자료는 목적에 필요한 범위로 줄이고 접근·보관·삭제 흐름을 추적합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 처리 목적과 민감도·필수 필드를 정합니다.
2. 모델 입력·로그·추적·캐시에 최소한의 자료만 남깁니다.
3. 권한·보관 기간·삭제·공급자 조건을 검증합니다.

## 예제로 확인하기

```python
record={"ticket":"T7","issue":"배송 지연","email":"private@example.test"}
allowed={"ticket","issue"}
payload={k:v for k,v in record.items() if k in allowed}
assert "email" not in payload
print(payload)
```

## 결과를 해석하기

허용 필드만 선택하는 예제입니다. issue 본문 안에도 개인 정보가 있을 수 있어 필드 선택만으로 충분하지 않습니다. 실제 흐름 전체의 목적·접근·보관을 점검해야 합니다.

## 실무에 옮기기 전

간단한 마스킹이나 해시만으로 재식별 위험이 없어지지 않습니다. 제공자의 보관·학습 사용·지역·하위 처리 조건은 실제 계약과 설정을 확인해야 합니다. 실제 업무에서는 문제 진단에 필요한 증거를 정의해 최소 수집합니다. 공급자 처리 조건과 내부 목적·권한을 실제 설정 및 계약 담당 검토와 연결합니다.
