# 데이터 드리프트·성능 저하·모니터링

> **먼저 한 문장:** 입력 분포 변화와 실제 예측 품질 저하를 구분하고 정답이 늦게 오는 상황까지 관측합니다.

출시할 때 잘 맞던 모델이 새로운 계절이나 고객 집단에서는 틀릴 수 있습니다. 입력과 실제 결과의 변화를 관찰하면 언제 평가·조사·재학습이 필요한지 판단할 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"drift-monitoring","view":"words"}
```

## 작은 예로 이해하기

겨울 판매 자료로 만든 모델을 여름에 사용하면 기온과 상품 구성이 달라집니다. 입력 분포가 바뀐 것이 데이터 드리프트입니다. 이것만으로 예측이 반드시 틀렸다고 알 수는 없으므로 실제 판매 결과가 도착하면 오차도 확인합니다. 입력 변화와 결과 품질을 따로 관찰해야 합니다.

## 익숙한 장면과 연결하기

가게 손님 구성이 달라졌다고 매출이 반드시 나빠지는 것은 아닙니다. 변화 신호와 실제 업무 결과를 따로 확인해야 합니다.

**비유의 한계 — 이 점은 달라요:** 분포 변화 알림은 성능 저하의 증명이 아닙니다. 반대로 평균이 비슷해도 특정 집단이나 입력·정답 관계가 바뀌면 실패할 수 있습니다.

## 직접 확인하기

입력 변화 → 실제 품질 → 조사·대응 순서로 읽어 보세요. 뒤의 과정에서 필요한 것이 앞에서 어떻게 준비되는지 찾습니다. 숫자는 읽는 순서이며 모든 상황이 정확히 세 단계라는 뜻은 아닙니다.

```learning
{"slug":"drift-monitoring","view":"explore"}
```

# 데이터 드리프트·성능 저하·모니터링 · 작동 원리

평균 차이만 보는 학습용 신호로, 통계 검정이나 성능 하락 판정은 아닙니다. 실제로는 표본 수·계절성·입력 수집 오류와 정답 기반 성능을 함께 확인합니다.

## 전체 흐름부터 보기

```learning
{"slug":"drift-monitoring","view":"trace"}
```

## 예제와 내부 동작

아래 자료를 읽을 때 **입력 → 바뀌는 값이나 상태 → 결과**를 찾아보세요. 모르는 말은 밑줄 표시를 눌러 뜻을 확인할 수 있어요.

<!-- classroom-reference:start -->
## 읽기 전 길잡이

입력 분포 변화와 실제 예측 품질 저하를 구분하고 정답이 늦게 오는 상황까지 관측합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 입력·출력·정답·업무 결과의 기준 기간을 정합니다.
2. 자료 분포와 구간별 성능·지연·오류를 관측합니다.
3. 변화 원인을 조사하고 재평가·재학습·복구를 선택합니다.

## 예제로 확인하기

```python
baseline=[10,11,9]; live=[20,21,19]
mean=lambda x:sum(x)/len(x)
gap=abs(mean(live)-mean(baseline))
assert gap==10
print("평균 차이:",gap)
```

## 결과를 해석하기

평균 차이만 보는 학습용 신호로, 통계 검정이나 성능 하락 판정은 아닙니다. 실제로는 표본 수·계절성·입력 수집 오류와 정답 기반 성능을 함께 확인합니다.

## 실무에 옮기기 전

분포 변화 알림은 성능 저하의 증명이 아닙니다. 반대로 평균이 비슷해도 특정 집단이나 입력·정답 관계가 바뀌면 실패할 수 있습니다. 실제 업무에서는 알림은 재학습의 자동 명령이 아니라 조사의 출발점으로 둡니다. 수집 오류·계절성·실제 관계 변화에 따라 대응을 다르게 선택합니다.

## 확인 질문
