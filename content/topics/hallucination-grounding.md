# 환각·출처·모르는 답 처리

> **오늘의 질문** · 자연스럽게 말하면 믿어도 될까?

먼저 그림을 눌러 바꿔 볼까요? 답이 달라지는 모습을 천천히 관찰해 보세요.

```learning
{"slug":"hallucination-grounding","view":"explore"}
```

## 익숙한 장면과 연결해요

확신 있게 발표하는 사람이 정확한 자료를 봤는지는 별개입니다. 발표에 붙은 참고문헌도 실제 주장을 뒷받침하는지 확인해야 합니다.

## 선생님과 한 번 정리해요

그럴듯하게 틀린 답을 그대로 업무에 쓰면 문제가 커질 수 있습니다. 주장과 출처를 확인하고 모를 때 멈추는 경로를 두면 답변의 신뢰도를 더 구체적으로 점검할 수 있습니다.

**한 줄로 말하면:** 자연스러운 문장과 근거 있는 답은 다르므로 주장별 출처와 모를 때의 행동을 검증해야 합니다.

```learning
{"slug":"hallucination-grounding","view":"words"}
```

**비유의 한계도 알아둘까요?** 출처 ID가 존재하거나 인용 형식이 맞아도 주장을 지지한다는 보장은 없습니다. 모델의 자신감 표현도 보정된 확률로 볼 수 없습니다.

```learning
{"slug":"hallucination-grounding","view":"recall"}
```

# 한 장면씩 원리를 따라가요

이번에는 **주장 나누기 → 근거 확인 → 모르면 유보** 순서로 살펴볼게요. 먼저 다음에 무슨 일이 생길지 생각하고, 그림을 한 칸씩 넘겨 보세요.

```learning
{"slug":"hallucination-grounding","view":"trace"}
```

## 여기서 연결해 봐요

자연스러운 문장과 근거 있는 답은 다르므로 주장별 출처와 모를 때의 행동을 검증해야 합니다.

왜 이런 순서가 필요한지 말로 설명할 수 있으면 좋아요. 코드와 자세한 설명은 아래에 준비했어요. 낯선 기호는 입력·바뀌는 값·결과로 나눠 읽어 봐요.

## 읽기 전 길잡이

자연스러운 문장과 근거 있는 답은 다르므로 주장별 출처와 모를 때의 행동을 검증해야 합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 답변에 필요한 주장과 근거 문서를 연결합니다.
2. 자료가 없거나 상충하면 유보·추가 질문으로 처리합니다.
3. 인용의 존재·내용 일치·자료 버전을 검사합니다.

## 예제로 확인하기

```python
sources={"p2":"환불 가능 기간 7일"}
claim={"text":"환불 가능 기간 7일","source":"p2"}
assert claim["source"] in sources
assert claim["text"] in sources[claim["source"]]
print("이 작은 예제의 직접 인용 일치 확인")
```

## 결과를 해석하기

문자열이 그대로 들어 있는 직접 인용의 형식과 일치만 검사합니다. 일반적인 문장의 함의·예외·상충 근거 검증은 이 코드보다 어렵고 별도 평가와 사람 검토가 필요할 수 있습니다.

## 실무에 옮기기 전

출처 ID가 존재하거나 인용 형식이 맞아도 주장을 지지한다는 보장은 없습니다. 모델의 자신감 표현도 보정된 확률로 볼 수 없습니다. 실제 업무에서는 업무 오류 비용에 맞춰 근거 검토와 사람 연결 수준을 정합니다. 모든 질문에 답하는 비율만 높이지 않고 오답과 과도한 유보를 함께 측정합니다.

## 4. 수정 방법

## 5. 재검증

```learning

```

## 이유까지 말하면 더 좋아요

“나는 이 방법을 골랐어. 중요한 조건은 이것이고, 대신 이런 부담은 감수할게.”처럼 설명해 보세요. 그러고 나서 조건을 하나 바꾸면 같은 선택을 할지도 생각해 봐요.

## 읽기 전 길잡이

같은 개념도 업무의 규모, 오류 비용, 운영 역량에 따라 적용 방식이 달라집니다. 아래 비교는 특정 제품의 성능 순위가 아닌 선택 기준입니다.

| 선택 | 얻는 점 | 감수할 점 |
|---|---|---|
| 자유로운 답변 | 다양한 표현·종합 | 근거 없는 확장 위험 |
| 근거 제한 답변 | 추적과 검토가 쉬움 | 답 유보·검색 누락 관리 |
