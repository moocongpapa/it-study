# 구조화 출력·JSON Schema·의미 검증

> **먼저 한 문장:** 모델 출력을 프로그램이 쓰려면 형식 제약과 파싱뿐 아니라 업무상 값의 의미도 검증해야 합니다.

AI의 답을 사람이 읽는 데서 그치지 않고 프로그램으로 처리하려면 일정한 형식이 필요합니다. 형식을 맞추는 일과 내용이 맞는지 확인하는 일을 나눠야 잘못된 자동 실행을 줄일 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"structured-outputs","view":"words"}
```

## 작은 예로 이해하기

회의록에서 담당자와 기한을 뽑아 프로그램에 넣으려 합니다. JSON Schema로 담당자는 문자열, 기한은 정해진 형식이라고 요구하면 형태를 맞추기 쉬워집니다. 하지만 날짜 형식이 맞아도 실제 회의에서 합의한 날짜인지는 별도 확인이 필요합니다. 모양이 맞는 것과 내용이 맞는 것은 다른 검사입니다.

## 익숙한 장면과 연결하기

주문서 칸을 정해도 수량 칸에 9999를 적은 주문이 실제 가능한지는 따로 확인해야 합니다. 양식과 업무 규칙은 다른 검사입니다.

**비유의 한계 — 이 점은 달라요:** 스키마에 맞는 JSON도 거짓 값이나 권한 없는 행동을 포함할 수 있습니다. 제공자별 지원 스키마·거절·중단 응답의 계약도 확인해야 합니다.

## 직접 확인하기

사례가 형식 검사과 의미 검사 중 어디에 해당하는지 골라 보세요. 고른 뒤 나오는 이유를 읽고, 같은 기준으로 다음 사례를 판단합니다.

```learning
{"slug":"structured-outputs","view":"explore"}
```

```learning
{"slug":"structured-outputs","view":"recall"}
```

## 읽기 전 길잡이

모델 출력을 프로그램이 쓰려면 형식 제약과 파싱뿐 아니라 업무상 값의 의미도 검증해야 합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 필수 필드·타입·허용 범위로 출력 계약을 정의합니다.
2. 지원되는 구조화 모드로 생성하고 파싱·스키마를 검사합니다.
3. 권한·참조 존재·업무 조건을 서버에서 검증합니다.

## 예제로 확인하기

```python
import json
result=json.loads('{"quantity":2,"sku":"A"}')
stock={"A":3}
assert type(result["quantity"]) is int
assert 0<result["quantity"]<=stock[result["sku"]]
print("형식과 재고 조건 통과")
```

## 실무에 옮기기 전

스키마에 맞는 JSON도 거짓 값이나 권한 없는 행동을 포함할 수 있습니다. 제공자별 지원 스키마·거절·중단 응답의 계약도 확인해야 합니다. 실제 업무에서는 다운스트림 행동이 중요한 경우 구조화 출력과 서버 의미 검증을 함께 둡니다. 형식 재시도도 횟수·비용을 제한하고 실패 시 안전한 상태를 유지합니다.

## 5. 재검증
