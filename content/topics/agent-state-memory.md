# 에이전트 상태·메모리·세션 분리

> **먼저 한 문장:** 대화·작업 상태·장기 기억은 수명과 권한이 다르므로 범위·버전·삭제 규칙을 나누어 저장합니다.

여러 차례의 대화와 작업을 이어가려면 무엇을 기억할지 정해야 합니다. 작업 상태와 기억의 범위를 알면 다른 사용자의 정보가 섞이거나 오래된 판단을 다시 쓰는 오류를 줄일 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"agent-state-memory","view":"words"}
```

## 작은 예로 이해하기

민수의 예약 상담 다음에 지수의 상담이 들어왔습니다. 민수의 예약번호가 지수의 대화에 섞이면 안 됩니다. 현재 작업 상태, 이 대화의 기록, 오래 보관할 선호 정보는 범위와 수명이 달라요. 누구의 정보인지와 언제 지울지를 각각 정합니다.

## 익숙한 장면과 연결하기

회의 메모와 진행 중인 체크리스트, 회사의 공식 기록은 역할이 다릅니다. 한 사람의 메모를 다른 고객의 서류에 붙이면 안 됩니다.

**비유의 한계 — 이 점은 달라요:** 오래 기억한다고 더 정확한 것은 아닙니다. 모델이 요약한 기억에는 오류가 들어갈 수 있고 사용자 정정·만료·삭제가 필요합니다.

## 직접 확인하기

현재 작업 상태과 다음에 쓸 기억을 번갈아 선택하세요. 바로 아래 설명에서 무엇을 공유하고 무엇이 달라지는지 비교합니다. 버튼을 누르는 것보다 차이를 한 가지 말해 보는 것이 목표예요.

```learning
{"slug":"agent-state-memory","view":"explore"}
```

```learning
{"slug":"agent-state-memory","view":"recall"}
```

## 읽기 전 길잡이

대화·작업 상태·장기 기억은 수명과 권한이 다르므로 범위·버전·삭제 규칙을 나누어 저장합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 세션·사용자·조직과 상태의 수명을 정의합니다.
2. 작업 단계·도구 결과를 구조화해 저장합니다.
3. 기억을 꺼낼 때 권한·유효 기간·출처를 검증합니다.

## 예제로 확인하기

```python
memory={("org-A","user-1"):"선호 언어: 한국어"}
assert memory.get(("org-B","user-1")) is None
print(memory[("org-A","user-1")])
```

## 결과를 해석하기

조직과 사용자 ID를 함께 키로 쓰는 격리 예제입니다. 실제 저장소는 키 규칙만이 아니라 서버 권한 검사·수명·동시 갱신·삭제를 보장해야 합니다.

## 실무에 옮기기 전

오래 기억한다고 더 정확한 것은 아닙니다. 모델이 요약한 기억에는 오류가 들어갈 수 있고 사용자 정정·만료·삭제가 필요합니다. 실제 업무에서는 기억할 업무 목적과 보관 수명을 먼저 정합니다. 사실과 추정·사용자 선호를 구분하고 출처·시각·정정 경로가 없는 기억을 중요한 결정의 근거로 사용하지 않습니다.
