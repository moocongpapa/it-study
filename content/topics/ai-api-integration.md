# AI API·스트리밍·재시도·취소

> **먼저 한 문장:** AI 호출은 실패·지연·부분 응답을 가진 외부 의존성이므로 시간·비용·취소와 재시도를 함께 설계합니다.

AI를 웹 화면이나 회사 업무에 연결하려면 요청을 보내고 실패와 응답을 처리해야 합니다. API 연결의 흐름을 알면 화면 시연을 실제로 운영 가능한 기능으로 옮길 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"ai-api-integration","view":"words"}
```

## 작은 예로 이해하기

답이 한 글자씩 나타나는 동안 사용자가 취소를 누를 수 있습니다. 화면 표시만 멈추면 서버의 생성은 계속될 수도 있어요. 요청 실패 때는 다시 시도할지 정하되, 이미 실행한 작업을 반복하지 않도록 구분해야 합니다. 스트리밍, 취소, 재시도는 사용자가 기다리는 경험과 서버 비용에 함께 영향을 줍니다.

## 익숙한 장면과 연결하기

전화를 걸어 긴 설명을 듣는 동안 끊기거나 상대가 늦게 답할 수 있습니다. 다시 전화할 때 같은 일을 두 번 처리하지 않도록 문맥을 남겨야 합니다.

**비유의 한계 — 이 점은 달라요:** 스트리밍 조각은 완성된 JSON이나 완결된 판단이 아닙니다. 클라이언트 취소가 공급자의 계산·과금을 즉시 멈춘다고 가정하지 않습니다.

## 직접 확인하기

검증한 요청 → 모델 응답 → 실패·중단 처리 순서로 읽어 보세요. 뒤의 과정에서 필요한 것이 앞에서 어떻게 준비되는지 찾습니다. 숫자는 읽는 순서이며 모든 상황이 정확히 세 단계라는 뜻은 아닙니다.

```learning
{"slug":"ai-api-integration","view":"explore"}
```
