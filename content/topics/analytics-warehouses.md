# 웨어하우스·레이크와 분석 모델

> **먼저 한 문장:** 원본 자료 보관과 일관된 지표 제공은 서로 다른 목적이며 저장·변환 계층을 나누어 설계합니다.

실제 주문을 처리하는 곳에 무거운 분석을 함께 돌리면 서비스가 느려질 수 있습니다. 분석용 저장소를 따로 이해하면 어떤 자료가 얼마나 최신인지도 알고 사용할 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"analytics-warehouses","view":"words"}
```

## 작은 예로 이해하기

사진, 로그, 원본 CSV를 그대로 보관하는 장소와 ‘하루 매출’처럼 뜻이 정해진 보고서용 표는 쓰임이 다릅니다. 데이터 레이크는 다양한 원본 보관에, 웨어하우스는 구조화된 분석에 주로 쓰입니다. 이름만 고르기보다 어떤 자료를 누가 어떤 기준으로 조회할지 정하는 것이 먼저입니다.

## 익숙한 장면과 연결하기

창고의 원재료와 진열대의 완제품을 떠올려 보세요. 원본을 보관하는 것만으로 누구나 같은 기준의 상품을 바로 고를 수 있는 것은 아닙니다.

**비유의 한계 — 이 점은 달라요:** 레이크·웨어하우스의 경계는 제품마다 겹칩니다. 이름만으로 품질·비용·일관성이 보장되지 않으며 실제 테이블 형식과 실행 엔진의 성질을 확인해야 합니다.

## 직접 확인하기

업무 처리 저장소과 분석용 저장소을 번갈아 선택하세요. 바로 아래 설명에서 무엇을 공유하고 무엇이 달라지는지 비교합니다. 버튼을 누르는 것보다 차이를 한 가지 말해 보는 것이 목표예요.
