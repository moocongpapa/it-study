# 작업 분해·추정·불확실성

> **먼저 한 문장:** 큰 일을 확인 가능한 작은 결과로 나누고, 추정값에 숨어 있는 가정과 불확실성을 함께 드러냅니다.

큰 일을 며칠이라고만 말하면 무엇이 빠졌고 왜 달라졌는지 설명하기 어렵습니다. 확인 가능한 결과로 나누고 가정을 남기면 준비·검토·대기 시간도 계획에 포함할 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"wbs-estimation","view":"words"}
```

## 작은 예로 이해하기

‘예약 사이트 완성’은 너무 커서 얼마나 걸릴지 가늠하기 어렵습니다. 신청 화면, 중복 예약 방지, 취소 처리, 확인 테스트로 나눠 보세요. 처음 연결하는 서비스가 있다면 확실한 작업 시간과 조사에 필요한 시간을 구분합니다. 추정은 약속된 정답이 아니라 현재 정보와 가정을 담은 예상입니다.

## 익숙한 장면과 연결하기

집 수리를 사흘로 잡아도 철거 뒤 배관 상태를 모르면 일정은 흔들립니다. 방별 작업을 나누고 자재 대기와 전문가 확인을 표시하면 왜 시간이 달라지는지 설명할 수 있습니다. 소프트웨어도 작업량과 기다림을 나눠 봅니다.

**비유의 한계 — 이 점은 달라요:** 사람의 개발 속도를 벽돌 수처럼 고정할 수는 없습니다. 추정은 약속의 근거를 토론하기 위한 예상이며 새로 알게 된 조건에 따라 갱신해야 합니다.

## 직접 확인하기

작게 나누기 → 가정과 범위 → 조사 후 갱신 순서로 읽어 보세요. 뒤의 과정에서 필요한 것이 앞에서 어떻게 준비되는지 찾습니다. 숫자는 읽는 순서이며 모든 상황이 정확히 세 단계라는 뜻은 아닙니다.

# 작업 분해·추정·불확실성 · 작동 원리

범위가 같은 추정끼리 비교해야 합니다. 순수 코딩 시간만 더한 값과 검토·배포 대기를 포함한 값은 다릅니다. 범위를 나타내는 숫자는 보장된 확률 구간이 아니며 가정과 근거가 없으면 정밀한 소수점도 도움이 되지 않습니다.

아래 자료를 읽을 때 **입력 → 바뀌는 값이나 상태 → 결과**를 찾아보세요. 모르는 말은 밑줄 표시를 눌러 뜻을 확인할 수 있어요.

## 읽기 전 길잡이

큰 일을 확인 가능한 작은 결과로 나누고, 추정값에 숨어 있는 가정과 불확실성을 함께 드러냅니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 완료를 확인할 수 있는 결과 단위로 일을 나누고 누락을 점검합니다.
2. 검토·통합·대기·운영 준비를 포함해 낙관·기준·비관 가정을 적습니다.
3. 짧은 조사 작업으로 큰 불확실성을 줄이고 실제 결과로 추정을 갱신합니다.

## 예제로 확인하기

```markdown
# 작업 분해: 문서 검색 시범
- 문서 수집: 접근 권한 확인, 샘플 정리
- 검색 구현: 분할, 색인, 검색 평가
- 사용자 검증: 화면 연결, 오류 안내, 상담원 테스트
- 운영 준비: 모니터링, 담당자 교육, 되돌리기

# 추정 기록
- 작업: 색인 성능 확인
- 범위: 대표 문서 200건, 가상 사례
- 예상: 1~3일, 문서 형식이 일정하다는 가정
- 불확실성: 표와 스캔 이미지 비율
- 다음 행동: 반나절 샘플 조사 후 다시 추정
```

## 결과를 해석하기

범위가 같은 추정끼리 비교해야 합니다. 순수 코딩 시간만 더한 값과 검토·배포 대기를 포함한 값은 다릅니다. 범위를 나타내는 숫자는 보장된 확률 구간이 아니며 가정과 근거가 없으면 정밀한 소수점도 도움이 되지 않습니다.

## 실무에 옮기기 전

사람의 개발 속도를 벽돌 수처럼 고정할 수는 없습니다. 추정은 약속의 근거를 토론하기 위한 예상이며 새로 알게 된 조건에 따라 갱신해야 합니다. 실제 업무에서는 불확실성이 큰 부분에 조사 시간을 먼저 쓰고 반복 작업은 실제 소요 분포를 참고합니다. 추정치를 개인 성과 목표로 고정하면 낙관 보고를 유도할 수 있으므로 가정 변경과 완료 결과를 함께 검토합니다.

## 확인 질문

**답과 이유:** 같은 숫자라도 포함 범위와 가정이 다르면 의미가 달라지므로 근거가 필요합니다.
