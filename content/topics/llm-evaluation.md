# LLM 평가셋·루브릭·사람 평가

> **먼저 한 문장:** LLM 품질은 업무별 평가 사례와 명시적인 채점 기준으로 측정하고 자동 채점의 편향도 점검합니다.

몇 개 질문에 답을 잘했다고 실제 업무 전체에서도 좋다고 할 수는 없습니다. 대표 사례와 같은 채점 기준을 갖추면 변경 전후의 품질을 비교하고 실패를 찾을 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"llm-evaluation","view":"words"}
```

## 작은 예로 이해하기

답변 AI 두 개를 비교할 때 ‘더 친절해 보인다’만으로 고르면 어려운 질문에서의 오류를 놓칠 수 있습니다. 같은 질문 묶음으로 사실 일치, 필요한 내용 포함, 근거 부족 때의 대응을 각각 확인합니다. 쉬운 질문과 까다로운 질문을 함께 넣고 사람의 검토 기준도 맞춰야 비교가 의미 있습니다.

## 익숙한 장면과 연결하기

글쓰기 시험을 채점할 때 문장 길이만 보지 않고 사실·논리·요구 충족을 따로 보는 것과 같습니다. 채점자끼리 같은 기준을 이해해야 합니다.

**비유의 한계 — 이 점은 달라요:** 다른 LLM이 채점했다고 객관적 진실이 보장되지는 않습니다. 순서·문체·채점 모델의 편향과 평가 자료 누출, 표본의 대표성을 검토해야 합니다.

## 직접 확인하기

대표 문제 → 같은 채점 기준 → 실패·편향 점검 순서로 읽어 보세요. 뒤의 과정에서 필요한 것이 앞에서 어떻게 준비되는지 찾습니다. 숫자는 읽는 순서이며 모든 상황이 정확히 세 단계라는 뜻은 아닙니다.

```learning
{"slug":"llm-evaluation","view":"explore"}
```

```learning
{"slug":"llm-evaluation","view":"recall"}
```

## 읽기 전 길잡이

LLM 품질은 업무별 평가 사례와 명시적인 채점 기준으로 측정하고 자동 채점의 편향도 점검합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 대표·예외·안전 사례와 기준 답·근거를 만듭니다.
2. 정확성·근거성·업무 성공을 분리해 채점합니다.
3. 사람 일치도와 실제 운영 실패를 반영해 평가셋을 갱신합니다.

## 예제로 확인하기

```python
cases=[{"grounded":True,"task_done":True},{"grounded":False,"task_done":True},{"grounded":True,"task_done":False}]
rate=sum(c["grounded"] and c["task_done"] for c in cases)/len(cases)
assert abs(rate-1/3)<1e-9
print(round(rate,3))
```

## 결과를 해석하기

두 조건을 모두 충족한 사례는 3건 중 1건입니다. 작은 수치는 설명용입니다. 실제 평가에서는 실패 유형별 비율과 표본 수·불확실성, 치명적 오류를 별도로 보고합니다.

## 실무에 옮기기 전

다른 LLM이 채점했다고 객관적 진실이 보장되지는 않습니다. 순서·문체·채점 모델의 편향과 평가 자료 누출, 표본의 대표성을 검토해야 합니다. 실제 업무에서는 배포 통과 기준을 변경 전에 정하고 핵심 실패를 회귀셋에 추가합니다. 전체 평균 외에 고위험 시나리오의 실패를 독립적으로 차단합니다.
