# 에이전트 평가·추적·실패 재현

> **먼저 한 문장:** 에이전트는 최종 문장뿐 아니라 도구 선택·중간 상태·권한·비용까지 과제 단위로 평가해야 합니다.

에이전트가 틀린 결과를 냈을 때 마지막 문장만 봐서는 원인을 알기 어렵습니다. 검색·모델·도구 호출의 흐름과 평가를 남기면 실패와 비용이 생긴 단계를 찾을 수 있습니다.

## 먼저 알아둘 말

```learning
{"slug":"agent-evaluation-tracing","view":"words"}
```

## 작은 예로 이해하기

AI가 마지막에는 올바른 예약 정보를 답했지만, 중간에 검색을 20번 반복했다면 비용과 속도에는 문제가 있습니다. 최종 답뿐 아니라 어떤 도구를 어떤 순서로 불렀는지, 어디서 오래 걸렸는지를 기록합니다. 그러면 같은 실패 조건을 다시 만들어 수정 효과를 확인할 수 있습니다.

## 익숙한 장면과 연결하기

택배가 도착했는지만 볼 것이 아니라 잘못된 주소에 들렀는지, 분실했다 복구했는지 배송 경로를 확인하는 것과 비슷합니다.

**비유의 한계 — 이 점은 달라요:** 추적 로그에 모든 원문을 남기면 민감정보가 새어나갈 수 있습니다. 성공 문장만으로 실제 외부 행동이 완료되었다고 판단해서도 안 됩니다.

## 직접 확인하기

단계 기록 → 결과 평가 → 실패 경로 추적 순서로 읽어 보세요. 뒤의 과정에서 필요한 것이 앞에서 어떻게 준비되는지 찾습니다. 숫자는 읽는 순서이며 모든 상황이 정확히 세 단계라는 뜻은 아닙니다.

