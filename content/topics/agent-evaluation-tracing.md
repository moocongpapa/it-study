## 읽기 전 길잡이

에이전트는 최종 문장뿐 아니라 도구 선택·중간 상태·권한·비용까지 과제 단위로 평가해야 합니다. 아래 예제는 외부 시스템에 연결하지 않는 작은 학습용 사례입니다. 입력, 처리 조건, 결과를 순서대로 살펴보세요.

1. 과제 성공·금지 행동·비용 기준을 정합니다.
2. 도구 호출과 관측·상태 전환을 추적 ID로 연결합니다.
3. 실패 사례를 재현하고 단계별 원인과 회귀를 검사합니다.

## 예제로 확인하기

```python
trace=[{"step":"search","ok":True},{"step":"write","ok":False}]
success=all(s["ok"] for s in trace)
assert not success
print("최종 성공:",success)
```

## 결과를 해석하기

필수 단계가 모두 성공했는지 보는 단순 모형입니다. 실제 과제는 잘못된 대상·부분 성공·금지 행동·중복 효과도 검사해야 하고 결과를 외부 상태로 확인해야 합니다.

## 실무에 옮기기 전

추적 로그에 모든 원문을 남기면 민감정보가 새어나갈 수 있습니다. 성공 문장만으로 실제 외부 행동이 완료되었다고 판단해서도 안 됩니다. 실제 업무에서는 트레이스는 원문 최대 수집이 아니라 필요한 증거와 식별자 중심으로 설계합니다. 재현 가능한 모의 도구로 실패 경로를 평가하고 운영 결과와 연결합니다.
